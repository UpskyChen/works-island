# 作品島現行版（假 2.5D）技術說明

> 站主 Sky 撰寫，2026-10-27 依 `main`（`5776b1f`）的程式碼核對過；與程式不符的地方已改正，改了哪些見文末「核對紀錄」。

## 一、本體是什麼

本體是 2D 的 SVG＋CSS＋原生 JavaScript，沒有 WebGL、沒有 Three.js、沒有真正的 3D 座標與模型。它的立體感全部來自平面繪圖的三種錯覺技術（下一節）。這不是缺點定性 — 它換來的是載入輕、iPad 順、文字全是真 DOM（可搜尋、可無障礙操作）；代價是立體感有天花板，拉遠看仍偏平面插畫。

## 二、立體感的三個騙法

1. **島體厚度＋岸線＋倒影**：每座島的 SVG 輪廓除了頂面，還畫出側面（崖面）、一圈岸線，島下方在水面上有倒影。眼睛靠「頂面＋側面＋影子」讀出高度 — 這是假 2.5D 最核心的一招。
2. **前後遮擋**：樹木、建築、地標等景物依所在位置的前後關係決定繪製順序，後面的被前面的部分遮住。大腦用遮擋判斷深度，所以島上東西一多，空間感就出來。
3. **分層視差**：滑鼠移動、拖曳地圖（或 iPad 開啟「傾斜視差」）時，水面、倒影、島體、雲朵以不同幅度位移。圖層移動速度不同，是平面畫面假裝有深度的經典手法。點選作品時鏡頭平滑推近並微調傾角，也是同一家族的效果。

## 三、島是怎麼生出來的

- 島形是不規則輪廓（有海灣、岬角），座標存在 `site/data/layout.json`，由 `tools/gen-islands.mjs` 以固定種子產生後寫死 — 每次載入形狀都一樣，不是即時亂數。
- 三種寬度各有一套版面：wide（≥1000px）、medium（≥600px）、narrow（作品節點只顯示編號）。判斷依據是**地圖區塊本身的寬度**，不是整個螢幕的寬度。
- 新增作品不用改版面檔：放不下時，程式自動把那座島等比例放大並推開鄰島。
- 島與島之間有木造步道（拱橋 arch／棧道 deck，可調拱高與彎度），水面另有沙洲、礁石、小浮島當裝飾。步道只是裝飾；作品間真正的關聯是彩色弧線連線，圖例分開標示，兩者不混。

## 四、動態的規則

動態分兩類：

- **常駐緩動與鏡頭**：分層視差、點作品時的鏡頭推近，以及水波、雲、兩艘小船的緩慢移動。
- **一次性的互動回饋**：第一次載入時島浮起、文字淡入；選中連線時虛線流動幾圈；作品節點閃兩下；「已逛完」章蓋下；右側導覽貓眨眼、搖尾巴。

系統開啟「減少動態效果」（prefers-reduced-motion）時，視差與上面所有動畫全數關閉，鏡頭改為直接跳到定位，畫面靜止但功能完整 — 這條是現行版做得對的地方，真 3D 版必須保留。

## 五、為什麼看起來還是淡（站主裁決與技術對應）

站主的實際觀感是「淡雅、沒有為之一亮、看不出跟改版前的差別」。對應到實作，原因是力道、不是缺功能：

- 側面厚度畫得薄，正常觀看距離下崖面幾乎讀不到；
- 五區色票是低飽和粉彩，各區色彩個性接近，掃視時沒有焦點；
- 視差幅度刻意含蓄；第一屏的動態（開場浮起、水波、雲、小船）都很微弱，沒有一眼抓住目光的動態錨點。

結論：這一版的技術選型（假 2.5D）本身有上限，三個力道就算全開，也只能逼近「精緻的平面圖」。要跨過那條線，才有開真 3D 實驗 repo 的理由 — 實驗的成敗判準也因此定為「第一屏截圖並排，立體感與色彩一眼可辨」。

## 七、留好的後門：插圖資產槽

每個分區可用一張透明底 WebP 插圖（約 16:10、單張 300KB 以下、只畫島與地景、不含文字）取代 SVG 地塊。這些規格是約定，程式不會檢查。

- 五個分區 id：`campus`、`subjects`、`games`、`tools`、`frozen`。
- 圖片放 `site/assets/zones/<分區 id>.webp`（這個資料夾放第一張圖時再建立）。
- 在 `layout.json` 的 `art` 把該區由 `null` 改成相對 `site/` 的路徑，例如 `"campus": "assets/zones/campus.webp"`。

圖片載入成功才隱藏該區 SVG 地形與倒影（景物、標籤、節點、連線仍疊在上層）；載入失敗自動退回 SVG 版。真 3D 實驗若不成立，這條是假 2.5D 版日後升級外觀的另一條路。
