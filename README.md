# 阿喵老師的作品島

阿喵老師（Upsky）的個人作品展示站（v2：2D 活潑互動版）。純靜態網站：沒有後端、表單、追蹤或登入，不載入任何外部 CDN 或字體（使用系統字體）。

- **島嶼探索**：五個分區是五座六角地塊小島，以裝飾木橋相連。點作品膠囊，鏡頭會聚焦並滑出詳情卡；滑過或點選分區，左側卡顯示該區摘要。
- **清單模式**：同一份資料依分區列成清單，可展開詳情，每列都能「在島上定位」。
- **右側面板**：你的探索進度、搜尋、狀態篩選、「分區／連線」分頁，並與地圖雙向連動。
- **其他**：帶我逛逛（自動導覽）、網址深層連結（例如 `#xikou-3d-campus`）、連線開關、＋／－ 縮放、拖曳與雙指縮放、鍵盤操作（Tab／Enter／Esc）、深淺色模式、減少動態效果模式。

## 本機預覽

JS 使用瀏覽器原生 ES modules，必須用靜態伺服器開啟（直接雙擊 `index.html`、以 file:// 開啟無法運作）：

```bash
cd site
python3 -m http.server 8000
```

然後用瀏覽器開 <http://localhost:8000/>。手機或 iPad 在同一個網路下，可開 `http://<電腦 IP>:8000/` 實機測試。

## 如何新增一件作品

**只要改 `site/data/works.json`**：在 `works` 陣列加一筆，存檔後重新整理即可。地圖位置由程式依分區（教材區依學科子區）自動排列，不需要填座標；某區放不下時，島會自動長高。

| 欄位 | 必填 | 說明 |
|---|---|---|
| `id` | ✓ | 英文小寫與連字號，不可重複，例如 `"new-tool"`；也是深層連結網址 `#new-tool` |
| `name` | ✓ | 作品名稱。地圖膠囊顯示短名稱（去掉全形括號說明；太長時取第一個空格前的部分），完整名稱顯示在卡片與清單 |
| `zone` | ✓ | 分區：`campus`、`subjects`、`games`、`tools`、`frozen` |
| `subzone` | 教材區必填 | 學科子區，例如 `"國語"`；放進原本的空子區後，該子區的空地告示牌會自動消失 |
| `status` | ✓ | 狀態文字。含「待／尚未／升級中／需登入」顯示為 ◐「狀態有註記」，凍結區顯示 ❄「凍結」，其餘顯示 ✓「上線中」 |
| `problem`、`approach`、`result` | | 問題／做法／成果；留空字串就不顯示該列 |
| `audience` | | 對象 |
| `links` | | `[{ "label": "按鈕文字", "url": "網址" }]`，照順序顯示為按鈕 |
| `tags` | | 標籤陣列（也會被搜尋到） |
| `displayNote` | | 卡片上的「說明」框 |
| `freezeReason` | | 卡片上的「凍結原因」框 |
| `relationLabel` | | 延伸作品標籤；有這個欄位的作品會自動排在主作品的右下方 |
| `subzoneItems`、`subzoneNote` | | 站內小區清單（目前只有阿喵的遊戲世界使用；子頁一律連回第一個連結） |

其他需要一起更新的地方：

1. `meta.totalWorks` 與 `zones` 裡該區的 `count`：網站顯示的數字一律由實際筆數計算，這兩個欄位只用來對帳。若對不上，瀏覽器 console 會出現 `[對帳]` 提示。
2. 若新作品與其他作品有關聯，在 `connections` 加一筆 `{ "from": "...", "to": "...", "label": "...", "style": "solid" }`（虛線用 `"dashed"`）。地圖只會畫這裡列出的線。
3. 作品編號依 `works` 陣列順序自動產生。

## 地圖版面設定（data/layout.json）

這個檔案只放版面，不含任何作品內容：

- `layouts.wide`／`medium`／`narrow`：三種螢幕寬度的島嶼排列。
  - `rows`：每列放哪些分區、各島寬度。
  - `cellOrder`：教材區子區的排列順序。
  - `bridges`：哪兩座島之間畫裝飾木橋。
  - `narrow` 版（手機）的節點只顯示編號。
- `props`：各區標題列旁的小插畫。
- `subzoneProps`：子區角落的小插畫。
- `scenery`：散布在空地塊上的景物與地標建築。程式會自動避開節點與文字。
- `art`：插圖資產槽（見下一節）。

## 插圖資產槽（日後升級外觀用）

每個分區都可以用一張插圖取代 SVG 地塊。設定方式：

1. 把圖片放在 `site/assets/zones/`，命名為 `<分區>.webp`，例如 `campus.webp`、`subjects.webp`。
2. 在 `site/data/layout.json` 的 `art` 裡，把該區的 `null` 改成路徑，例如 `"campus": "assets/zones/campus.webp"`。

圖片規格建議：

- **格式**：WebP；背景透明；單張 **300KB 以下**，iPad 載入較順。
- **比例與尺寸**：約 **16:10**，例如 1600×1000。圖片會依比例縮放、置中放進該島的範圍，各島長寬比不同，構圖請留邊。
- **內容**：只畫島與地景。**不要把任何文字、作品名稱、編號畫進圖片**；分區標籤、作品節點、連線一律由網站疊在圖片上層。

運作方式：

- 圖片載入成功，才隱藏該區的 SVG 地塊、景物與倒影。
- 圖片不存在或載入失敗，自動退回 SVG 版。此時瀏覽器 console 會出現一筆 404 紀錄，屬正常現象；不想看到就把 `art` 改回 `null`。
- `art` 為 `null` 時完全不發出圖片請求。

## 小貓嚮導的固定提示句（供站主審稿）

小貓的對話泡泡只會出現兩種文字：

**1. 固定提示**（全部列在 `site/js/guide.js` 的 `HINTS`，共 8 句）

| 時機 | 文字 |
|---|---|
| 進站 | 嗨！點一座島或一個編號看看。 |
| 點選分區 | 這一區的作品都列在卡片上，點一件看看。 |
| 點選作品 | 卡片下方的按鈕可以直接打開作品。 |
| 逛完一區 | 這一區你逛完了！ |
| 15 件全部看過 | 全部作品都看過了，謝謝你逛完整座島！ |
| 開始「帶我逛逛」／導覽中 | 我帶你一件一件看，隨時可以按停止。 |
| 停止導覽 | 導覽停下來了，想看哪裡就點哪裡。 |
| 按「重新開始」 | 進度清除了，我們重新出發吧！ |

**2. 資料檔原文**（以較小字顯示在提示句下方，原樣不改）

- 點選分區、逛完一區時：該分區的 `name`，例如「教材區」。
- 點選作品、導覽中：該作品的 `status`，例如「已上線（桌機已測，iPad 實機待驗收）」。

小貓不會說出任何資料檔沒有的作品描述、成效或評價。

## 你的探索進度

- 記錄「這個瀏覽器看過哪幾件作品」：打開一件作品的詳情卡就算看過。
- 一區全部看過，地圖與面板上會蓋「已逛完」章。
- 只存在訪客自己瀏覽器的 `localStorage`（鍵名 `works-island:visited:v1`），不送出任何網路請求；面板上的「重新開始」可清除。
- 無法使用 `localStorage` 時（隱私模式、被封鎖），進度只在本次瀏覽中計算，面板會顯示提示，其他功能不受影響。
- 這只是介面回饋，不代表對作品的任何評價。

## 顯示規則（display-rules.js）

原始資料檔裡有幾句話，是給製作者的施工指示（例如「不要猜子頁網址」「展示時不要寫成已完成」）或計件說明（例如「計 1 件」），另外還有「（站主本人 README 原意）」這類出處括號。依站主決定：

- 資料檔一字不改，改由 `site/js/display-rules.js` 在**顯示時**刪掉這些片段。
- 規則只做逐字刪除，不改寫、不新增任何字；每條規則都列在該檔，可逐條覆核。
- 其中一條規則刪掉口說練習 result 裡提到 `englishspeak` 舊站的那句，避免排除項目出現在站上。
- 若之後修改資料檔，讓某條規則的原文對不上，該規則會自動失效，並在 console 顯示 `[display-rules]` 提示。
- 新增作品時，直接寫成要給訪客看的文字即可，不需要新增規則。

## 部署（GitHub Pages）

GitHub Actions 會把 `site/` 資料夾發佈到 GitHub Pages：

1. 到 repo 的 **Settings → Pages**，Source 選 **GitHub Actions**（只需設定一次）。
2. 合併或推送到 `main` 分支，`.github/workflows/pages.yml` 就會自動部署（只有 `site/` 或 workflow 有變動時才觸發）。也可以在 **Actions** 頁手動執行 “Deploy site to GitHub Pages”。
3. 網址為 `https://<帳號>.github.io/works-island/`。

**回退**：在 GitHub 上 revert 該次合併的 commit，Actions 會自動重新部署前一版。

## 注意

- `site/data/works.json` 會隨網站公開（任何人都能直接打開這個檔案），裡面包含 `excluded` 清單與註記原文；頁面上不會顯示這些內容。若不希望它們能被直接讀到，可以從 `site/data/works.json` 刪掉 `excluded` 區塊，網站不使用它。
- 本站不放任何聯絡方式；`intro.contact` 目前為 `null`。
